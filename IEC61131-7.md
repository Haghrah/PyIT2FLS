Here is a full description of the IEC 61131-7 (FCL) standard, the subset of it implemented by `pyit2fls.FCL`, followed by a comprehensive example that demonstrates its most important and common features.

-----

## ℹ️ Description of the IEC 61131-7 (FCL) Standard

**IEC 61131-7** is the part of the IEC 61131 family of standards (better known for IEC 61131-3, which standardizes PLC programming languages such as Ladder Diagram and Structured Text) that defines **Fuzzy Control Language (FCL)** — a plain-text format for describing fuzzy logic controllers for industrial and embedded use.

### 1\. Purpose and Significance

FCL was designed for the world of **Programmable Logic Controllers (PLCs)** and embedded fuzzy controllers, where an XML-based format like [IEEE 1855 (FML)](IEEE1855.md) is often impractical:

  * **Text-based and compact:** FCL files are small, plain-text documents that are easy to embed in firmware, transmit over slow links, or edit on a device with limited resources.
  * **PLC-native semantics:** Its `FUZZIFY`/`DEFUZZIFY`/`RULEBLOCK` structure mirrors the way PLC programs are already organized into named blocks, making it a natural fit alongside Structured Text and Ladder Diagram code in the same controller project.
  * **Interoperable:** Like FML, it lets a fuzzy controller designed in one tool (e.g. [jFuzzyLogic](http://jfuzzylogic.sourceforge.net/), fuzzyTECH, or `pyit2fls`) be understood by any other FCL-compliant tool or runtime.

### 2\. Core Components of an FCL Document

An FCL file describes a single `FUNCTION_BLOCK`, structured around four kinds of nested blocks:

1.  **`VAR_INPUT` / `VAR_OUTPUT`:** Declares the crisp input and output variables of the function block, each as `name : REAL;`.

2.  **`FUZZIFY <variable>` / `DEFUZZIFY <variable>`:** Defines the linguistic terms of an input (`FUZZIFY`) or output (`DEFUZZIFY`) variable.

      * **`TERM <name> := (x1,y1) (x2,y2) ... ;`:** Defines a linguistic term (like `cold`, `warm`, `hot`) as an explicit piecewise-linear membership function — a list of `(x, y)` points, rather than a named shape like FML's `<triangularShape>`. This is FCL's native, most general term representation.
      * **`RANGE := (min .. max);`:** The variable's universe of discourse (optional — if omitted, it is inferred from the extent of the declared terms).
      * `DEFUZZIFY` blocks additionally specify a **`METHOD`** (e.g. `COG` for Center of Gravity) and a **`DEFAULT`** value used when no rule fires.

3.  **`RULEBLOCK <name>`:** Defines the *logic* of the controller.

      * You specify the core inference operators here: **`AND`** (e.g. `MIN`, `PROD`), **`OR`** (e.g. `MAX`), **`ACT`** (the activation/implication method), and **`ACCU`** (the accumulation method used to combine rule outputs).
      * **`RULE n : IF ... THEN ... ;`:** A single IF-THEN rule. Clauses are combined with `AND`/`OR`, and a clause can be negated with `IS NOT`. A rule may end with an optional `WITH <weight>` to scale its influence.

4.  **`FUNCTION_BLOCK <name>` / `END_FUNCTION_BLOCK`:** Wraps the whole document.

### 3\. Scope implemented by `pyit2fls.FCL`

The full IEC 61131-7 standard also defines Structured Text method bodies and support for chaining multiple `RULEBLOCK`s together (the output of one feeding the input of another) — both squarely aimed at PLC programming environments. `pyit2fls.FCL` implements the **core Mamdani subset** used by the overwhelming majority of real-world FCL files instead: a single `FUNCTION_BLOCK` with `VAR_INPUT`/`VAR_OUTPUT`, `FUZZIFY`/`DEFUZZIFY` blocks, and a single `RULEBLOCK`. See `markdown docs/FCL.md` for the exact list of supported keywords and known limitations (e.g. rule weights and the `ACCU` setting are parsed but not applied during evaluation).

One limitation worth calling out here: `pyit2fls`'s underlying `T1Mamdani`/`T1TSK` evaluation engines only combine a rule's antecedent clauses with AND — there is no support for `OR`-combining multiple clauses *within a single rule*. Model an OR relationship as two separate rules that share the same consequent instead (their contributions are then combined by the usual max-based rule accumulation), as shown in rules 1 and 2 of the example below.

## Example: "Smart Tipper" Fuzzy Controller

This is the FCL equivalent of the Mamdani half of the ["SmartTipper" FML example](IEEE1855.md), calculating a restaurant tip based on two inputs: `service` and `food`.

```
FUNCTION_BLOCK SmartTipper

VAR_INPUT
    service : REAL;
    food : REAL;
END_VAR

VAR_OUTPUT
    tip : REAL;
END_VAR

FUZZIFY service
    TERM poor := (0,1) (2,0.6) (5,0);
    TERM good := (3,0) (5,1) (7,0);
    TERM excellent := (6,0) (8,1) (10,1);
    RANGE := (0 .. 10);
END_FUZZIFY

FUZZIFY food
    TERM bad := (2.5,1);
    TERM tasty := (6,0) (10,1);
    RANGE := (0 .. 10);
END_FUZZIFY

DEFUZZIFY tip
    TERM low := (0,0) (5,1) (10,0);
    TERM average := (10,0) (15,1) (20,0);
    TERM high := (20,0) (25,1) (30,1);
    METHOD : COG;
    DEFAULT := 0;
    RANGE := (0 .. 30);
END_DEFUZZIFY

RULEBLOCK MamdaniRules
    AND : PROD;
    OR : MAX;
    ACT : MIN;
    ACCU : MAX;

    RULE 1 : IF service IS poor THEN tip IS low;
    RULE 2 : IF food IS bad THEN tip IS low;
    RULE 3 : IF service IS good THEN tip IS average;
    RULE 4 : IF service IS excellent AND food IS tasty THEN tip IS high WITH 0.8;
    RULE 5 : IF service IS NOT poor AND food IS tasty THEN tip IS high;
END_RULEBLOCK

END_FUNCTION_BLOCK
```

Loading this file with `pyit2fls.FCL`:

```python
from pyit2fls.FCL import FCL

with open("SmartTipper.fcl") as f:
    fcl_text = f.read()

my_fcl = FCL()
name, variables, rules = my_fcl.parse_fcl(fcl_text)
system = my_fcl.generate(variables, rules)
print(system.evaluate({"service": 8, "food": 9}))
```
